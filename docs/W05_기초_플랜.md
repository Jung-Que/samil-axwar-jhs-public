## 0. 한 문장 (가안)

**"새 약속은 기존 약속과 '쓸 수 있는 날짜의 능력'을 먼저 통과해야 밖으로 나간다."**
입찰 하나가 들어오면 이미 한 약속(수주장부 안팎)과 라인별 능력을 날짜 단위로 맞춰 보고,
지킬 수 있는 수량·시점만 조건부로 제안하며, 회신·승인·정정이 들어올 때마다 그 약속 원장을 다시 계산한다.

## 1. 누구의 어떤 결정을 개선하나

| 항목 | 내용 |
|---|---|
| 주 사용자 | Corevia 영업(입찰 담당)과 생산관리(능력 담당). 승인자는 CEO/이사회(입찰 참여·투자), 영업 임원(C-101 조건) [원본] |
| 결정 | C-201에 참여할지, **어떤 수량을 언제부터 어떤 조건으로** 제안할지, 증설·전환(OPT-01/02)을 무엇과 묶을지 |
| 지금의 어려움 | ① 공장 평균 가동률(87%)로 보면 라인 병목(L-02 97%)이 가려진다 ② 기존 약속이 출하 기준 자료로만 모여 진행 중 주문·Masil 발주가 빠진다 ③ 입찰 마감(3주)과 납품 개시일을 같은 것으로 다루기 쉽다 ④ 승인 조건이 제안서에 반영됐는지 확인하는 단계가 없다 ⑤ 바이어 회신이 생산관리·재무로 돌아가지 않는다 (`W05_대형수주_기존약속.md` §2) |
| 개선 | 약속 원장 + 라인×월 능력을 엔진이 계산하고, AI가 근거·반대증거·미확인을 묶어 조건부 제안안을 쓰며, 사람의 승인·거절과 외부 회신에 따라 제안 조건·작업·상태가 갱신된다 |
| 시작과 끝 | 시작: RFP 접수 사건. 끝: 승인된 조건이 붙은 제안 품목(수량·시점·조건), 생성된 확인 요청·작업, 갱신된 약속 원장과 이벤트 기록. 다음 사건(회신·정정·거절)이 이 상태를 읽고 재판단한다 |

## 2. 시스템이 맡는 역할과 앞뒤 업무

```
바이어(모의) ──RFP·회신──▶ [영업] ──사건──▶ ┌──────────── 약속 조율 시스템 ────────────┐
                                           │ 약속 원장 · 라인×월 능력 · 적격 능력일     │
생산관리 ◀──확인 요청 / 회신──────────────▶ │ 엔진 계산 → AI 근거·초안 → 사람 승인        │
재무·전략 ◀─환율·원가·300억 조건──────────▶ │ → 제안 조건 · 작업 · 상태 갱신 · 이벤트 기록 │
CEO/이사회 ◀─상신 / 승인·조건부·거절──────▶ │                                          │
영업 임원 ◀──C-101 조건 협의 작업─────────▶ │                                          │
Masil SCM ◀──더마 공급 확인·보호 슬롯─────▶ └──────────────────────────────────────────┘
```

- 앞 업무: 수주(`sales_orders_cv`), 능력 스냅샷(`strat_capacity_cv`), 증설안(`strat_capex_plan_cv`), Masil 발주(`sc_purchase_orders_ms`).
- 뒤 업무: 제안서 제출(영업), 생산계획 반영(생산관리), 300억 배분표 반영(그룹 재무), 더마 보충 계획(Masil SCM).

### 4.3 상태

- **입찰**: `접수 → 검토중 → 상신 → 승인 | 조건부 승인 | 거절 → 제안 작성 → 제출 → 회신 대기 → 재검토 → 수주 | 실주 | 보류`
- **제안 품목**: `미확정(확인 대기) → 잠정(조건부) → 제안됨 → 합의 | 철회`
- **기존 약속**: `확정(원본) | 추정 납기 | 보호(그룹 내 장부 밖) | 변경 요청 → 고객 동의 | 거절`
- **확인 요청**: `요청 → 회신 → 반영 | 기한 초과 → 재요청·보류`
- **근거**: `최신 | 낡음`(의존 입력이 바뀌면 낡음, 재판단 전까지 상신 잠금)

## 6. 필수 확장 (추천): 적격 능력일 기반 분할 약속

- **무엇:** 증설·전환안을 "승인일 + 리드타임"으로만 보지 않고, 설치 → 처방 재검증 → 고객 승인까지 거친 **적격 능력일**을 계산해, 그 날짜 이후의 능력만 제안 수량에 쓴다. OPT-02는 M-B 재계약·처방 재검증이 선행조건이다 [원본].
- **왜:** 승인일 기준으로 보면 OPT-02가 2026-08-24에 생긴 능력처럼 보이지만 [계산], 재검증 전에는 납품할 수 없다. 이 차이가 지연 페널티(월 3%)로 바로 이어진다.
  게다가 RFP는 "더마 물량은 F1의 더마 전용 라인에서만 생산 가능"이라고 적는데 OPT-02는 **F2 해외공장** 전환이다 [원본]. 바이어가 F2 생산지를 받아들이는지가 적격 능력일의 한 요소가 된다(확인 요청).
- **확장이 없을 때와 차이(시연에서 비교):** 확장 없음 → 연간 수량을 한 번에 약속, 초기 월 부족분이 페널티로 쌓임. 확장 있음 → 분할 일정(초도 수량·시점)과 "적격일 이전 미확정" 조건이 제안 품목 상태에 들어가고, 바이어 질의서에 초도 납품일 확인이 생김.
- **적격 능력일 계산(두 시나리오):** 설치 이후 기간(밸리데이션 + 고객 처방 승인)은 원본에 없어 [가정]으로 두고 화면에 표시한다. 화장품 안정성시험 가이드라인 원문은 확보하지 못해 근거가 약하다(도메인 문서 §5-3).

| 안 | 설치 완료 [계산, 7/06 승인 가정] | 적격 A: +4주 [가정] | 적격 B: +12주 [가정] |
|---|---|---|---|

- **연결:** W04(대체 원료·사용 승인)와 같은 대상(M-B)을 공유한다.

## 7. 다른 부서 영향 (추천): Masil SCM의 더마 공급

- **그 부서의 목표·제약:** Masil 더마 4종은 Corevia가 100% 공급하고 [원본 Business_Process_Map], 안전재고 최소 4주인데 커버가 2.2~2.9주다 [계산 W01]. 발주 SPO-0001~0004 88,000 EA는 6/22~6/26 발주, 리드타임 12주라 9/14~9/18 입고가 필요하다 [원본·계산].
- **주업무의 영향:** C-201 PL-02 물량은 같은 L-02(97%)와 OPT-02 능력을 쓴다. 7~8월 L-02는 기존 B2B 약속만으로 월 생산의 약 90%가 찬다 [F14]. Masil 발주는 Corevia 수주장부에 없어서 [원본] 지금 흐름에서는 이 충돌이 보이지 않는다.
- **실제 반영:** Masil 발주를 `보호` 약속으로 원장에 넣고(합성 매핑 표시), PL-02 제안의 초기 월 수량에서 먼저 뺀다. 바이어가 초도를 앞당기면 Masil 슬롯과 충돌 → Masil SCM 확인 요청과 그룹 판단 작업이 생기고, 회신 전에는 해당 제안 품목이 `미확정`으로 남는다.
- **보조 영향:** OPT-01(180억)은 그룹 300억에서 Celtonic 1차 150억·Masil 방어 수요와 경합한다 [계산 W05 §1-5]. 이사회 조건("선행조건 충족 시 단계 집행" [원본])을 결정 객체의 조건으로 받아 OPT-01 의존 물량을 `조건부`로 묶는다. 배분 최적화는 하지 않는다.

## 10. 제공 BPMN에서 바꾸는 것

1. RFP 접수 직후 시스템이 약속 원장·라인 능력을 만든다(생산관리 수작업 취합 제거). 생산관리는 **확인 요청에 회신**하는 역할로 바뀐다.
2. 승인 게이트를 `승인 | 조건부 | 거절`로 나누고, 조건을 제안 품목에 붙여 **제출 전 자동 점검**한다(원본 게이트 뒤 검증 단계 부재 보완).
3. 바이어 회신이 생산관리·재무로 돌아가 재판단을 일으킨다(회신 순환 추가).
4. 기존 고객 약속 변경은 영업 임원 레인으로 분리한다(원본 권한 유지).
5. 원본 권한(입찰·투자 = CEO/이사회)은 바꾸지 않는다. 추가한 `조건부 승인`은 이사회 방침 "선행조건 충족 시 단계 집행"을 표현하는 교육용 가정이다.
